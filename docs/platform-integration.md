## Existing platform boundaries — checked against local code on 2026-10-11

Treat the following as the integration baseline, with proposed OTIO work explicitly separate from shipped capabilities.

- **Harvest owns acquisition and normalization.** Reuse dataset/provider workflows, media registration, provenance, and transcript normalization. Do not add a second LOC harvester or transcription pipeline inside OTIO or Fotostory. Read Harvest's instructions before scheduling pipeline work; use its current `DatasetInfo`/workflow path rather than deprecated stage commands.
- **Folio is the catalog interchange boundary.** A folio is normalized SQLite data identified by a `provider/dataset` code, referenced by string across application boundaries. Preserve the folio code and source row key; a URL or local Doctrine ID is not a substitute for source identity.
- **ZM serves source records/media to the story application.** Fotostory is the repository name and photo experience; Voxstory is the oral-history experience in the same shared story application. Neither experience is the conceptual parent of the other. Keep shared editorial/player functionality reusable across them.
- **Folio sets define membership.** Harvest selectors/tags resolve the configured `survos_folio.folio_sets`; synced membership is recorded in `var/folio-sets/*.json`. Domains choose sets, not their membership. Do not introduce a manual parallel collection list for the archival gallery. `Tenant`, `TenantFolio`, and `FolioProfile` support branding/legacy photo routes; they are not replacements for current set membership, and full multi-folio tenant presentation is not yet implemented.
- **Sync is distinct from search indexing.** `harvest:sync` consumes the change feed (or full reconciliation), updates folios/set projections, then Fotostory's `HarvestSyncedListener` refreshes editorial sets. It does not rebuild Elasticsearch; `folioset:build` is a separate operator step. Vox's catalog/row browsing does not require an Elasticsearch index. Do not migrate Fotostory to Meilisearch merely because generic platform examples use it.
- **Vox playback is not shipped yet.** Vox currently browses sets and paginated ZM rows and links to original sources. Its row API does not serialize Page audio/transcript fields. The missing ZM media/transcript API is an explicit prerequisite for a real Vox-backed player; do not bypass it by opening local folio SQLite files, downloading archives, or reading the shared dataset database from Vox routes. A local file's existence does not establish playback readiness.

### Asset and transcript adapter contract (proposed)

Keep this adapter in application/integration code, outside the dependency-free OTIO core. Resolve a source using existing folio code, row key, and (when supplied) registered media ID. Harvest's registrar derives media identity through `MediaIdentity::idFromOriginalUrl($item->identityUrl())`; do not independently hash a thumbnail, IIIF URL, signed URL, or whichever URL happens to be displayed. Use the authoritative registry identity and retain source claims/provenance.

Have the serving API expose stable identity, source revision/checksum where available, media kind/MIME, duration and timebase when known, browser-playable rendition, rights/attribution, and transcript cues/segments with explicit units. This is a proposed contract to verify and implement at the ZM boundary, not an existing endpoint. Preserve source references in OTIO metadata and resolve current playback URLs at runtime. Cache the URL-free projection separately, or give URL-bearing responses a TTL bounded by URL expiry; include resolver/rendition revision in cache invalidation.

Harvest already has `TimecodedTranscriptParser` and transcript cue/segment types. Its LOC-style parser infers a turn's end from the next timed turn and leaves the final end unknown. Do not turn an unknown end into zero or claim those boundaries are word-accurate forced alignment. Preserve original text, speaker labels, source checksum and timing provenance; convert milliseconds to OTIO time only at the adapter boundary. Clip a displayed transcript to the selected source interval and map it to destination time; retain the untouched source transcript for matching and provenance.

Showcase's July handoff also records an `ai-tools` → mediary/`ai-workflow-bundle` AssemblyAI path and cached utterance data, with verification/deployment gaps at that time. Re-check current availability before reuse. A flat `ai:ocrText` claim is not a timed transcript. Do not generalize `ledger-bundle`'s scanned-form bounding boxes into audio timing.
